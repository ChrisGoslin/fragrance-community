# Skill: Build a Feature End-to-End

## When to use
When we want to add or change a concrete feature in one of the three apps
and the goal can be described in 1–3 sentences.

## Process

### 1. Clarify
- Which project (Fragrance App, Gardening DB, Financial Planner)?
- What does the user do, see, and get at the end of this feature?

### 2. Review
- What already exists in the codebase relevant to this feature?
- Any constraints from PROJECTS.md or prior architect decisions?

### 3. Plan
- Break the work into 3–7 steps (backend, frontend, DB, etc.).
- Identify the riskiest or most uncertain part.
- Confirm the plan with the user before starting.

### 4. Implement
- Work in small, reversible changes.
- Explain each significant change as it's made.

### 5. Review
- Use reviewer checklist: does it match the goal? Any obvious gaps?
- Tell the user what changed and how to test it manually.

### 6. Reflect
- Name 1–3 things learned.
- Propose any rules to add to CLAUDE.md or agent files.

## Output format
- Short plan (bullet list)
- Implementation notes (what changed and why)
- How to test manually
- What was learned / what to improve later
