# Skill: Project Audit

## When to use

When picking up an existing project for the first time, or after a long
gap, to understand what exists before making any changes.

## Process

### 1. Gather what exists

- Deployed URL (check it live)
- Codebase location (VSCode / GitHub repo)
- Specs or docs (Notion or elsewhere)
- Any notes from prior AI sessions (Gemini Gems, etc.)

### 2. Assess the deployed app

- What can a user actually do right now?
- What is broken or missing?
- What does the UX feel like?

### 3. Assess the codebase

- What stack is it built on?
- What is the folder structure?
- What is wired up vs stubbed out?

### 4. Assess the gap

- What is the shortest path to a real MVP?
- What are the 3 biggest blockers?
- What can be cut without hurting the core value?

### 5. Produce an audit report

- Current state summary
- MVP definition (what must work)
- Prioritised gap list
- Recommended next step

## Output format

- **Stack confirmed:** (language, framework, hosting)
- **What works today:** (bullet list)
- **What's missing for MVP:** (prioritised list)
- **Recommended first action:** (one concrete next step)
